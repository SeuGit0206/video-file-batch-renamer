## Reporting a Vulnerability

We take the security of our project very seriously. If you discover or suspect a security vulnerability, please do **NOT** open a public issue or pull request.

### Preferred Reporting Method

Please report all security vulnerabilities privately by reaching out to the security team or maintainers:

- **Email**: `shoumajp@gmail.com`
- **Subject Line**: `[SECURITY VULNERABILITY] <Brief Description>`

### What to Include in Your Report

To help us triage and investigate the issue as quickly as possible, please include as much of the following information as possible:

1. **Type of Issue**: (e.g., Buffer Overflow, Remote Code Execution, Path Traversal, XSS, Information Disclosure)
2. **Steps to Reproduce**: Detailed step-by-step instructions or proof-of-concept script.
3. **Affected Components**: Specific files, API endpoints, or services involved.
4. **Impact**: Potential consequences if exploited by a malicious actor.
5. **Possible Fix / Remediation**: Optional suggestions on how to resolve the issue.

---

## Response Timeline & Disclosure Policy

When a security vulnerability is reported:

1. **Acknowledgment**: We will acknowledge receipt of your vulnerability report within **48 hours**.
2. **Investigation & Triage**: The maintainers will investigate and determine the severity within **5 business days**.
3. **Patch & Release**: If verified, a patch will be prepared, tested, and released as part of a security update.
4. **Public Disclosure**: Once the fix is released, a security advisory will be published acknowledging your contribution (unless you request anonymity).

Thank you for helping keep this project safe for everyone!
